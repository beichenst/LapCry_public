# LapCry

LapCry 是一个**本地优先**的桌面数据处理工作台，用于编码、解码、加密、解密、哈希、
压缩、解析、提取、取证与数据分析。它以「操作（Operation）+ 配方（Recipe）」的方式
组织处理流程：把若干操作按顺序串联成配方，输入数据依次流过配方，得到输出结果。

输入、输出、配方与自定义脚本都只在**本机进程内**流转，不经过任何 LapCry 服务器；
程序不需要账号，也不包含云同步、遥测或在线翻译。

## 特性

- **完整操作库**：保留上游数据处理引擎的全部操作与配方语义，覆盖编解码、加解密、
  哈希与校验、压缩与归档、数据格式解析、取证与文件分析、图像处理等类别。
- **拖拽式配方**：从操作库拖入配方、拖拽排序、拖出删除，参数即时编辑。
- **自动 / 手动执行**：支持自动执行、手动执行、单步（Step）、断点、Fork 与寄存器。
- **多标签输入输出**：输入与输出支持文本、文件、文件夹，多标签并行处理，
  可设置字符编码与行尾，并导出结果。
- **自定义 JavaScript**：在隔离的本地 Worker 中运行自定义函数，支持函数体、
  超时与错误提示，网络 API 被禁用。
- **自定义函数库**：函数可命名、新增、编辑、删除、持久化，并作为操作加入配方。
- **双语界面**：中文与 English 可即时切换并持久化。
- **双主题**：浅色与深色主题可即时切换并持久化。
- **纯离线运行**：所有核心处理均在本机完成，适合离线与隔离网络环境。

> 说明：少数内置操作会按用户主动操作访问外部服务，例如地图、DNS over HTTPS、
> HTTP 请求等。除这些用户显式触发的功能外，输入与配方不会离开本机。

## 使用方法

### 界面概览

主界面自上而下分为三块：

- **顶部工具栏**：搜索框、运行控制（执行 / 单步 / 自动执行）、配方操作
  （载入 / 清空 / 保存）、设置与帮助入口。
- **中部配方区**：配方管线（Operation 列表）与操作库抽屉。每个操作为一张紧凑卡片，
  可设置参数、禁用、设断点、隐藏参数。
- **底部输入 / 输出区**：左侧输入、右侧输出，中间有可拖动的分隔条，
  可上下或左右调整区域大小。

### 典型流程

1. 用顶部搜索框或「操作库」抽屉查找操作，**双击**或**拖入**配方管线。
2. 在配方卡片中设置操作参数；可用卡片上的图标禁用操作、设断点或隐藏参数。
3. 在输入区输入、粘贴或拖入文件；支持文本、单文件、文件夹与多标签。
4. 开启「自动执行」，或点击「执行」生成输出；也可用「单步」逐操作执行。
5. 需要时把输出「保存到文件」，或在输出区直接复制结果。
6. 可将配方保存 / 载入为文件，便于复用与分享。

### 操作库与搜索

- 点击工具栏的操作库按钮打开抽屉，按类别浏览，或用搜索框按名称 / 描述过滤。
- 双击操作进入配方，或直接拖拽到配方管线中的目标位置。
- 操作卡片上的参数会即时生效；再次执行即可看到新结果。

### 配方

- **排序**：拖动操作卡片调整顺序。
- **删除**：将卡片拖出配方区，或使用卡片上的删除入口。
- **禁用**：禁用某操作后，执行时会跳过它，便于对比调试。
- **断点 / 单步 / Fork**：在执行流中暂停、逐步推进或复制分支。
- **寄存器**：在配方中存取中间值，便于复用。
- **保存 / 载入**：导出配方文件后可在其他机器或会话中载入。

### 输入与输出

- 输入支持**文本、文件、文件夹**，并可多标签并行；每个标签可独立设置字符编码与行尾。
- 输出区显示最近一次执行结果，可复制、切换为输入、或保存到文件。
- 拖动输入 / 输出之间的分隔条可调整可视区域大小，便于查看长文本。

### 设置

通过工具栏的「设置」入口打开，所有选项保存在本机并持久化：

- **主题**：浅色 / 深色。
- **语言**：中文（`zh-CN`）/ English（`en-US`）。
- **自定义函数**：管理命名自定义 JavaScript 函数（见下节）。
- **日志级别**：`silent` / `error` / `warn` / `info` / `debug` / `trace`。
- **更新地址（updateUrl）**：是否检查更新。
- **高亮器（showHighlighter）**、**自动换行（wordWrap）**。
- **显示错误（showErrors）** 与 **错误提示超时（errorTimeout）**。
- **使用 Win 键作为修饰键（useMetaKey）**：切换快捷键的修饰键方案。
- **自动 Magic（autoMagic）**：智能选择可能匹配的操作。
- **图片预览（imagePreview）**、**标签同步（syncTabs）**。

### 自定义 JavaScript 函数

在「设置 > 自定义函数」中新增 / 编辑命名函数，之后即可在配方里用
**Custom JavaScript** 操作按名称调用。

- 函数通过变量 `input` 取得当前数据，须返回字符串、字节数组、对象等可转换为
  字符串的值。
- 函数在隔离的本地 **Worker** 中运行，网络 API 被禁用。
- 可设置**超时（毫秒）**，超时后 Worker 被终止，不会阻塞主界面。
- 函数体、超时与错误信息都可在界面中编辑和查看。

## 从源码构建

完整说明见 `03_构建与打包\构建与打包说明.md`。最简方式：

```powershell
cd 03_构建与打包
powershell -ExecutionPolicy Bypass -File .\一键构建.ps1
```

脚本会依次安装依赖、静态检查、构建前端、运行非 UI 测试，并发布单文件 EXE，
最终产物输出到仓库根目录的 `dist\LapCry.exe`。

也可以手动分步执行：

```powershell
# 1) 安装依赖并构建前端
npm install
npm run build                     # 生产前端产物位于 build/prod/

# 2) 构建桌面程序（在此之前必须先完成前端构建）
dotnet publish desktop/LapCry.Desktop/LapCry.Desktop.csproj `
  -c Release -r win-x64 --self-contained true
```

桌面项目会自动把 `build/prod/` 内嵌进 EXE。构建依赖：Node.js `>=24 <27`、
npm、.NET 8 SDK。

## 隐私与安全边界

- 本地静态服务仅绑定 `127.0.0.1` 的随机端口，不暴露到局域网。
- 桌面窗口不允许导航到非回环页面；外部网页链接交由系统默认浏览器处理。
- 退出时关闭本地监听器并释放 WebView2 资源。
- 设置与自定义函数保存在本机 WebView2 用户数据目录的本地存储中；
  卸载前如需保留，请先导出配方或备份用户数据目录。
- 构建产物不包含开发机绝对路径或用户配方。

## 已知限制

- **内存占用偏高（待优化）**：空闲时实测进程组（LapCry + WebView2）约
  827 MB 工作集 / 623 MB 私有字节，高于「空闲不高于 250 MB」的目标。
  桌面进程本身约 120 MB，其余为 WebView2 渲染 / GPU 子进程。后续可通过
  延迟加载操作模块、减少首屏同步解析、按需创建 Worker 等方式降低占用。
  该指标不影响功能正确性，已列入优化清单。
- **依赖 WebView2 Runtime**：未安装 Evergreen WebView2 Runtime 时会提示安装；
  程序本身不内嵌浏览器内核，以控制体积。
- 首次启动因需释放内嵌资源，会略慢于后续启动。
